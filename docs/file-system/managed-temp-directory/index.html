creates temporary directories that are deleted when you close them, with a JVM shutdown hook as a fallback for directories that were never closed. Problem When creating temporary directories in Java, it's easy to forget to clean them up, leading to disk space issues. Solution implements , so a try-with-resources block deletes the directory and its contents. Every directory is also registered with a shutdown hook that deletes whatever is still open when the JVM exits. Usage Try-with-resources Path Deleted Only at Shutdown returns a plain and keeps no handle you can close, so the directory is only deleted by the shutdown hook: Directories created this way stay on disk until the JVM exits. In a long-running service, don't call it once per request or job; use with try-with-resources instead. Handling Deletion Failures throws a when deletion fails, for example when a file is still open on Windows. logs the failure and returns instead: After a failure, deletion deletes everything it can and the directory stays registered. Calling or again retries, and the shutdown hook retries at exit. Once the directory is deleted, later calls do nothing, and returns . Features Shutdown Hook The shutdown hook calls on every directory that is still open, so one directory that can't be deleted doesn't stop the others from being cleaned up. It runs when: The application exits normally is called The JVM receives termination signals like SIGTERM Shutdown hooks do not run if the JVM is killed forcefully (e.g., ) or crashes. The JVM runs shutdown hooks concurrently and in no set order, so this hook can run while Dropwizard's own hook is still stopping managed objects. Close directories that are used during shutdown yourself rather than relying on the hook. The logging framework's shutdown hook may also stop appenders first, so messages from this hook can be lost. The hook is registered when the class is loaded, once per classloader. Thread Safety Directories can be created from any thread. and are synchronized on the instance, so a second caller waits for the first caller's deletion to finish. Logging Creation and deletion are logged at DEBUG level, and deletion failures at WARN level, using SLF4J. File Attributes You can pass file attributes when creating the directory. On POSIX systems, the JDK already creates temporary directories readable only by their owner. This example also grants the owner's group read access: POSIX attributes are not supported on Windows, where throws . Recursive Deletion deletes a directory tree. When a file or directory can't be deleted, it keeps going and deletes everything else it can. then throws the first , with later failures attached as suppressed exceptions, and returns .
